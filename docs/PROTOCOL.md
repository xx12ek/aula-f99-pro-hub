# AULA F99 Pro 协议逆向笔记

面向想移植到别的语言 / 别的 AULA 型号的人。所有结论标注了可信度。

**可信度标记**
- ✅ **实测** —— 在真机上验证过，可复现
- ⚠️ **推断** —— 有证据支持但未独立验证
- ❓ **未知** —— 观察到了现象，机理不明

---

## 1. 设备

| 通道 | VID | PID | 集合 | 说明 |
|---|---|---|---|---|
| 有线 | `0x258A` | `0x010C` | `usage_page=0xFF00, usage=0x01` | HID feature report，**report id = 6** |
| 2.4G | `0x3554` | `0xFA09` | `usage_page=0xFF02, usage=0x02` | 中断端点，**report id = 0x13** |

✅ 有线设备会暴露多个 `0xFF00` 集合，**只有一个能用**。判断方法：发 `0x82`（身份查询）看是否有应答，或者看 feature report 长度是不是 520。

✅ 有线插着时，2.4G 接收器**完全不响应**任何命令（键盘固件互斥）。软件必须先试有线、失败再试无线。

## 2. 有线协议

### 帧格式（520 字节）

```
[0]     report id = 6
[1]     命令码
[2]     参数
[3]     0
[4]     总包数
[5]     当前包序号
[6..7]  payload 长度（小端）
[8..]   payload
```

✅ 读操作有个坑：**发完请求要 `sleep(0.015)`，再 `sleep(0.03)`，然后才 `get_feature_report`**。少了这两个延时读回来是空的或过期的。

### 命令表

| 码 | 名称 | 说明 |
|---|---|---|
| `0x82` | GET_INFO | 参数 `1` 返回身份，末字节 `0x58` = F99 Pro ✅ |
| `0x87` | GET_POWER | 参数 `2` 返回 `[电量%, 标志]` ✅ |
| `0x84` | GET_LED | 读配置页（128 字节）✅ |
| `0x04` | SET_LED | 写配置页 ✅ |
| `0x83` | GET_MATRIX | 读矩阵（512 字节 = 128 键 × 4 字节）✅ |
| `0x03` | SET_MATRIX | 写矩阵 ✅ |
| `0x86` | GET_RGB_TABLE | 读逐键颜色（378 字节）✅ |
| `0x06` | SET_RGB_TABLE | 写逐键颜色 ✅ |
| `0x11` | RESET | 恢复出厂 ✅ |
| `0x85` | GET_MACRO | 读宏库（10240 字节）✅ |
| `0x05` | SET_MACRO | 写宏库 ✅ |

### 电量字节

```
byte0 = 百分比 (0-100)
byte1 = 标志位
        0x10 置位 → 有线供电中
        0x01 → 电池供电
```

✅ **软件必须用 `flag & 0x10` 判断充电**，不能只看 `flag != 0` —— 无线状态下电池位也会置 1，那是「有电池」不是「在充电」。

## 3. 2.4G 协议

### 帧格式（20 字节）

```
[0]      report id = 0x13
[1]      命令码
[2]      总包数
[3]      当前包序号
[4]      (操作 << 4) | 本包数据长度
             操作 0 = 读，1 = 写
[5..18]  数据（最多 14 字节）
[19]     checksum = sum([0..18]) & 0xFF
```

✅ 单包数据上限 14 字节，长数据要分包。

### 命令表

| 码 | 名称 | 读写 | 说明 |
|---|---|---|---|
| `0x05` | GET_IDENTITY | 读 | 返回 `03 00 00 00 01 58 …` ✅ |
| `0x4A` | GET_BATTERY | 读 | `[电量%, 标志]` ✅ |
| `0x44` | GET_LED | 读 | 配置页 128 字节 ✅ |
| `0x04` | SET_LED | 写 | 配置页 ✅ |
| `0x41` | GET_MATRIX | 读 | **只有 504 字节**（126 键，缺最后 2 个键）✅ |
| `0x42` | GET_RGB_TABLE | 读 | 378 字节逐键颜色 ✅ |
| `0x43` | ? | 读 | 返回 512 字节全零，用途不明 ❓ |
| `0x49` | ? | 读 | 返回 490 字节，内容像固件代码段 ❓ |

### 2.4G 写不了的（已彻底排除）

✅ 扫过 `cmd ∈ {0x01,0x02,0x03,0x40,0x41,0x42,0x43,0x45,0x47} × op ∈ {1,2,3}` 共 24 组矩阵写入、18 组 RGB 写入，**读回全部不变**。

→ 无线通道的固件**只实现了读**。要写改键 / 逐键颜色 / 宏，必须插线。

## 4. 配置页（128 字节）

尾标记 `5A A5` 在 `0x7E`/`0x7F`。✅

| 偏移 | 含义 |
|---|---|
| `0x09` | 自定义颜色标志（1 = 用逐键颜色表）✅ |
| `0x0A` | 当前灯效编号（0 = 关闭）✅ |
| `0x18` | 休眠时间档位（见下表）✅ |
| `0x1A` | **固件模式标记**（1 = 键盘在固件自己的模式里）✅ |
| `0x38` | 旋钮旋转计数（每转一格 +1）✅ |
| `0x3A` | 灯效参数表起点（每槽 2 字节）✅ |
| `0x75` | 自定义模式的亮度 ✅ |

### 灯效槽位（`0x3A` 起）

每槽 2 字节：`[亮度, (速度 << 4) | 颜色]`

- 共 **34 槽**（到 `0x7C` 为止，再往后就是尾标记）
- 槽号 = `ui_index - 1`（**不是硬件灯效号**）✅
- 颜色 `0..6` = 红绿蓝黄品红青白，`7` = 随机 ✅

⚠️ `LedOptN` 里的编号是 **UI 序号**，按硬件灯效号去索引是错的 —— 会让灯效名和实际效果错位。

### 休眠档位

```
UI 秒:  60   90   120  180  240  300  600  900  1200
HW 值:  2    3    4    6    8    10   20   30   40
```

✅ 固件只认这 9 档，写别的值不接受。

### `0x1A` 固件模式

✅ 长按旋钮（约 2 秒）会让固件把 `0x1A` 置 1，此后：
- 旋钮直接调**键盘背光**，不再发任何按键给电脑
- 灯效被固件改成它自己的方案
- **键盘自己不会退出这个模式**

软件的处理：后台每 2 秒读一次配置页，发现 `0x1A == 1` 就写回 0，然后把灯效恢复。

## 5. 矩阵记录（每键 4 字节）

`KB.ini` 里的 8 位十六进制就是这 4 字节的大端写法（`0x07000004` → `07 00 00 04`）。✅

| `b0` | 类型 | 其余字节 |
|---|---|---|
| `0` | 普通键 / 组合键 | `b1` = 修饰掩码，`b3` = HID usage |
| `1` | 常用命令 | `b1` = 命令号（1..13）|
| `2` | Consumer 键 | `(b2 << 8) \| b3` = usage（**高字节在 b2**）|
| `3` | 宏 | `[3][模式][触发][槽位-1]` |
| `5` | 鼠标 | `b1` = 按键掩码（1 左 / 2 右 / 4 中）|
| `7` | 键盘内建功能 | `b3` = 功能号 |
| `8` | 键盘内建功能（复合）| `(b1,b2,b3)` 三元组 |
| `0x0D` | Fn 键占位 | — |

### 修饰掩码（`b0=0` 且 `b1≠0`）

```
0x01 Ctrl    0x02 Shift   0x04 Alt    0x08 Win
0x10 RCtrl   0x20 RShift  0x40 RAlt
```

✅ 右侧三个是实测扩出来的，早期只认低 4 位会导致 Shift/Alt 显示成乱码。

### `b0=7` 的固件功能

```
0x01 锁 Win        0x04 恢复出厂     0x05/06/07 蓝牙通道 1/2/3
0x08 2.4G          0x0A 游戏模式     0x0C 显示电量
0x18 Windows       0x19 Android      0x1A macOS      0x1B Linux
0x1D 旋钮/模式键
```

### 尾标记

每层矩阵最后 4 字节固定 `00 00 5A A5`，所以**只有 127 个可用键槽**（0..126）。✅

## 6. 逐键颜色（RGB 表）

✅ **最容易踩的坑**：不是按灯位交错存 `RGBRGB...`，而是**三个平面分开**：

```
data[0*126 + slot] = R
data[1*126 + slot] = G
data[2*126 + slot] = B
```

共 378 字节。搞成交错会让整块键盘颜色乱掉。

✅ **槽号 == 矩阵键号**。验证方法：出厂表里只有 9 个非黑槽，正好是 `#0 Esc`、`#9 A`、`#14 W`、`#15 S`、`#21 D`、`#83 ←`、`#88 ↑`、`#89 ↓`、`#95 →` —— 这组 WASD + 方向键不可能是巧合。

✅ 要让逐键颜色真正显示，必须**同时**满足：
- 配置页 `0x09 == 1`（自定义标志）
- 配置页 `0x0A == 19`（自定义灯效）

只改 `0x0A` 不够 —— 设备会收下但不显示。

## 7. 宏库

- 容量 **10240 字节**（`0x2800`）
- 有线走 `0x85` / `0x05`
- 2.4G **读不到**（`0x85` 被固件映射成了身份查询，返回的和 `0x05` 一模一样）✅
- 头部是 8051 机器码（`d3 90 0f 33 e0 94 e8 …`），宏数据从 `offset 4096` 开始 ✅

## 8. 系统侧（与键盘无关，但本软件需要）

### 音量
✅ `waveOutSetVolume` 是**死接口** —— 调用返回 0（成功）但音量纹丝不动。必须走 WASAPI `IAudioEndpointVolume`。

### 屏幕亮度
✅ 唯一能改的方式是 WMI `WmiSetBrightness`（只支持笔记本内屏，外接屏走 DDC/CI 不通）。

⚠️ WMI 写亮度是**异步的**，写完立刻读回来还是旧值。必须轮询最多 400 ms 等它生效。

⚠️ COM 接口指针（`_IAudioEndpointVolume`、WMI 连接）**有线程亲和性**，不能做成模块级全局变量 —— 否则界面线程和后台线程必有一方全线失败，而且错误会被 `except: pass` 吞掉，表现成「这个功能不支持」。

### Windows 原生 OSD
✅ **只能由真实硬件按键触发**。试过：

| 方式 | 亮度/音量变不变 | 弹不弹原生条 |
|---|---|---|
| 硬件发 Consumer 键 | 会 | **会** |
| WASAPI VolumeStepUp | 会 | 不会 |
| SendInput / keybd_event / 扫描码 | 音量会，亮度不会 | 不会 |
| WM_APPCOMMAND 音量 | 会（直接拉满）| 不会 |
| WM_APPCOMMAND 亮度 | 不会 | 不会 |
| WMI 改亮度 | 会 | 不会 |
| Dxva2 改亮度 | 不支持内屏 | — |

→ 所以想弹系统音量条，唯一办法是**别吞键、放行给 Windows**。

## 9. 原厂驱动遗留物

`OemDrv.exe` 里这些字符串说明了它的能力边界：

```
GetPower failed              ← 它有读电量功能
SyncCfg: ReadPower=%d
ShowPower                    ← 但 F99 Pro 的 KB.ini 里是 0，所以不显示
WheelMode / ShowModeSW / ShowSideLED   ← 模式开关与侧灯，F99 Pro 配置里完全没有
```

✅ `KB.ini`（三套：`F99Pro` / `F99` / `wired`）**全部** `ShowPower=0`，`text.xml` 里也**完全没有**「电量」词条 —— 官方是真的把这个功能藏了，不是坏了。
